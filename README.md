# 历史档案混合编码归一与索引保形

        面向一线复核人员的单服务数据工作台。样例数据随仓库提供，结论保留行号、原因码和原值。

        ## 业务模块

        - M1 文件采信：`/api/intake/run`
- M2 编码判定：`/api/encoding/detect`
- M3 字段保形：`/api/fields/normalize`
- M4 内容归一：`/api/content/normalize`
- M5 索引对账：`/api/reconcile`
- M6 批次导出：`/api/export/evidence.csv`
- M7 安全回收：`/api/reclaim`（续跑 `/api/reclaim/jobs/{job_id}/resume`）

        ## 核心规则

        候选解码必须完整且无替换字符；档号、盒号与超大流水号始终按字符串逐字保留。

        
## 证据表安全导出与回收（M7）

- 导出的证据表为 UTF-8（带 BOM）CSV：危险单元格（公式触发符含全角、前导零、超长数字串、布尔/日期、原文自带引号）前置 ASCII 单引号强制文本，表格软件打开不会执行公式、不会丢零或数值化。
- 防护只作用于导出文件，原文权威副本按 `run_id` 存证于服务端；首行清单与末列 `__guard__` 逐格登记防护位置，回收严格按清单剥离且仅剥离一个前缀，防护字符与原文可区分、不猜测还原。
- 回收时核验清单双摘要与服务端证据是否配套；篡改、错配、行数不符、防护标记不一致均整批拒收、零行入库。
- 回收作业持久化：中断重启可续跑，重试幂等不重复入库；同一份表（同文件摘要）并发回收只接纳一次。

## 启动

        ```bash
        docker compose up --build
        ```

        浏览器访问 `http://localhost:18210`。运行测试：

        ```bash
        docker compose exec -T app pytest -q
        ```

        ## 样例流程

        依次运行六个模块；最后在批次页复核输入、有效、隔离与输出合计。同一输入摘要重复执行时复用原 `run_id`。

        ## 已知不覆盖

        不处理加密文件与需要外部密钥的对象；不连接真实生产存储。
